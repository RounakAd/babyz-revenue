## Bug found and fixed while building this: edit-save silently finalised staged deletes

`POST /api/rows` did `writeStage(body.view || data, …)`. `view` is `state.data`, i.e.
**base minus pending deletions**. So saving anything (add *or* edit) rewrote STAGE with
those rows already removed while `pendingDeletes` still claimed they were pending.
`/api/confirm` then pushes STAGE → MAIN + REPO, and the "pending" rows were already
gone from it — so they silently became permanent and `/api/undo` could no longer bring
them back. Pre-existing; my feature just made it easy to hit.

Fix: new `mergeView(base, view)` in `server.js` rebuilds STAGE as
`base` with the view's ids retained per collection (i.e. staged rows removed again).
Proven with a node one-liner before and after.

## Verification

Wrote a jsdom harness (`.workbuddy-ai/verify/uiverify.js`, since deleted) that loads the
real `index.html` + `assets/app.js`, boots against the real `server.js` pointed at a
sandbox data dir, and drives the actual UI: 32/32 checks, run twice. It asserted both
directions — the rename reaches all 3 files with a pop-up on save, **and** on a hosted
(`github.io`) origin no Rename/Delete button or add panel is on screen and a synthesised
click writes nothing.

Harness lessons worth keeping:
* This jsdom build ships **no `fetch`** (the app's boot dies on `fetch is not defined`) —
  polyfill from Node's global and rewrite `http://127.0.0.1:8787` to the test server.
* It also ships no `ResizeObserver`; Chart.js needs it during boot.
* `getComputedStyle().display` **is** correct — use it to assert visibility.
  jsdom's `getClientRects()` returns 0 even for a plainly visible `<span>`/`<button>`
  (inline, no layout box), so it gives false "hidden" negatives. Do **not** stub
  `getClientRects`; use the computed display check.
* jsdom never fetches the `<link rel=stylesheet>`, so inline `assets/styles.css` into a
  `<style>` tag or the cascade — and therefore `body.is-live .readonly-hide` — is untested.
* Chart.js throws "Canvas is already in use" under jsdom after the page has rendered.
  Swallow it via `process.on('uncaughtException')` or it kills the harness.
